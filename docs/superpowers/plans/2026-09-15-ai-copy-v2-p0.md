# VibePin AI Copy v2 P0 Implementation Plan

## Scope And Frozen Decisions

- Base commit: `b2d8f36ca8b0ed262d19c4f0a436e1863205e2f7`.
- Integration branch: `codex/ai-copy-v2-p0-0915` in an isolated worktree.
- No deployment, push, production database mutation, P1 learning, P2 Trends sync, or browser extension work.
- `POST /api/ai-copy/v2/generate` returns one best version. A different angle is a new request.
- `trend_keywords` is the only P0 demand-signal source. Product, page, image, Board, and user input are relevance evidence only.
- Only `data_quality=official` is displayed as official. Other demand data is displayed as estimated or unknown.
- Server flag: `AI_COPY_V2_ENABLED=false`. Client flag: `NEXT_PUBLIC_AI_COPY_V2=false`.
- Navigation flag: `NEXT_PUBLIC_HIDE_LEGACY_DISCOVERY=false`; it hides Trends and Discover links only, never their routes.
- Analyze abuse ceiling: 200 requests per 5 minutes. Generate abuse ceiling: 150 requests per 5 minutes. These are not product quotas.
- Session lifetime: 24 hours.
- Feature-off routes return 404, unauthenticated routes return 401, rate-limited routes return 429, provider failures return 502, and an unrepaired invalid generation returns 422.
- Gemini implementation workers run sequentially because the active subagent-development workflow requires each task to be reviewed before the next implementation task begins. Each worker edits only its isolated worktree, commits locally, and never merges, pushes, deploys, or contacts production.

## Task 1: Freeze Contracts, Build Fact Cards, And Validate Copy

**Owner:** Gemini A (`google-antigravity/gemini-3.8-flash`)

**Files:**

- Create `web/src/lib/ai-copy/v2/types.ts`.
- Create `web/src/lib/ai-copy/v2/factCard.ts`.
- Create `web/src/lib/ai-copy/v2/validateCopy.ts`.
- Create `web/scripts/test-ai-copy-v2-facts.ts`.
- Register the test in the existing test registry/package scripts using the smallest possible diff.

**Contract:**

- `FactCardV1` contains `version: "fact-card-v1"`, `sessionId`, `draftId`, `locale`, and `facts`.
- Every fact contains `id`, `key`, `value`, `source`, `trustLevel`, and `claimPolicy`.
- `source` is one of `user_input | product_catalog | page_metadata | image_observed | board_context | ai_inferred`.
- `trustLevel` is one of `verified | asserted | observed | inferred`; never use numeric confidence.
- `claimPolicy` is one of `copy_allowed | descriptive_only | blocked`.
- Material, price, availability, efficacy, brand, and numeric commercial claims may be copied only from `verified` or `asserted` facts. Observed visual descriptions may be used only as non-commercial description. Inferred facts are never asserted as product facts.
- `KeywordEvidence`, `ValidationReport`, and `CopyResultV2` are also frozen in `types.ts` so later tasks import one contract.
- `CopyResultV2` contains one `title`, `description`, and `altText`, plus `generationId`, `keywordSetId`, `angleId`, actual used keyword IDs, a fact summary, degraded mode, and a structured validation report. It has no `clusterId`.
- Hard platform limits are title 100 characters and description 800 characters. Preserve existing short/standard/SEO-rich preferences as soft preferences.
- Exact keyword phrase occurrence is at most once in the title and twice in the description.
- Three consecutive repetitions of the same non-stopword fail as stuffing.
- Unsupported material, price, availability, efficacy, brand, and numeric claims fail.
- Validation produces issue codes and field locations and never repairs by truncating a sentence.

**TDD:**

1. Add tests first and run them to observe failure.
2. Implement the smallest pure modules needed.
3. Verify unsupported `silk`, `sterling silver`, therapeutic claims, price, inventory, brand, and numeric claims; length; stuffing; and valid grounded copy.

**Acceptance:**

- The focused test passes.
- Existing language and Shopify grounding tests remain green.
- No route, database, UI, or legacy behavior is changed.
- Worker commits locally and reports commit SHA, tests, and known risks.

## Task 3: Add Persistent Sessions, Security Gates, And V2 Routes

**Owner:** Gemini C (`google-antigravity/gemini-3.8-flash`)

**Files:**

- Create `backend/db/migrate_v70_ai_copy_v2_sessions.sql`.
- Port only the durable rate-limit module and required tests from historical v53/v54 work; do not cherry-pick unrelated commits.
- Create `web/src/lib/ai-copy/v2/sessionStore.ts` and server orchestration helpers.
- Create `web/src/app/api/ai-copy/v2/analyze/route.ts`.
- Create `web/src/app/api/ai-copy/v2/generate/route.ts`.
- Create focused route/session/rate-limit tests and register them.

**Persistence And Security:**

- `ai_copy_v2_sessions` stores user/workspace ownership, draft ID, analyze idempotency key, fact card, keyword evidence, last output, validation report, model/prompt versions, last generation idempotency key, generation count, status, expiry, and timestamps.
- Add unique analyze idempotency within the owning user. A repeated analyze request returns the original stored result.
- A repeated generate request with the same generation idempotency key returns the same stored output. A new key may create a new angle and update the last output.
- Enable RLS and add no permissive client policies. Only the server/service role accesses the table.
- Derive identity from the authenticated server session. Never accept client `userId` or trust a client-owned fact card/keyword set.
- Generate accepts only an unexpired session owned by the current user.
- Do not store full before/after user copy in analytics. If analytics is added, record only field-changed booleans, edit distance, and deleted keyword IDs.

**Analyze Route:**

- Input: `draftId`, `idempotencyKey`, locale/country, image/product/page/Board context, and user keywords.
- Build and persist `FactCardV1` and keyword evidence.
- Enforce server feature flag, authentication before paid work, validation, durable rate limit, ownership, and idempotency.

**Generate Route:**

- Input: `sessionId`, generation `idempotencyKey`, length preference, and optional angle request.
- Load trusted server-side session data and return one best `CopyResultV2`.
- Pass at most five selected keyword phrases to the model without requiring their use.
- In degraded mode, generate only from grounded product/image semantics.
- Validate output. Permit exactly one provider repair call for repairable formatting/keyword issues. Do not repair fact conflicts by inventing facts. A second failure returns 422 and never returns invalid copy.
- Do not truncate sentences as repair.

**TDD And Route Mocks:**

1. Add failing tests first.
2. Mock auth, service-role persistence, rate limiter, and AI provider; never call production or a real paid provider.
3. Cover 401, 404 feature-off, 429, ownership isolation, expiry, provider failure, analyze idempotency, generate idempotency, one repair, unrepaired 422, and no-keyword degradation.

**Acceptance:**

- Focused route/session/rate-limit tests pass.
- Migration is additive and RLS-safe.
- Legacy routes remain intact and v2 flags default off.
- Worker commits locally and reports commit SHA, tests, and known risks.
