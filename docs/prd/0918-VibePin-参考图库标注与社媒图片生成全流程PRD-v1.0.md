# VibePin 参考图库标注与社媒图片生成全流程 PRD v1.2

**日期：** 2026-09-20  
**状态：** 已同步 Studio 工作台 v1.2 裁决；产品方案，不代表已上线  
**Owner：** VibePin Creative Intelligence / Create Pin  
**覆盖范围：** 参考图采集、审核、标注、入库、商品分析、后台自动参考、风格配方、图片生成、自动质检、用户反馈与效果回流  
**首轮重点类目：** Home、Fashion、Beauty、Garden/Outdoor、Food & Drink、DIY & Crafts、Wedding  
**暂不纳入首轮：** Digital Products、自动视频生成、模型微调、生产数据库迁移

---

## 1. 文档目的

本 PRD 将此前分散在审核页、标注 JSON、生成测试、Fable/Codex 审查和稳定性验证中的需求，统一为一条可以开发、验收和持续扩展的产品链路：

> 采集自然流社媒参考图 → 去重与质量筛选 → 用户审核 → 结构化标注 → 形成可执行风格配方 → 用户从 URL、上传图片或现有图片卡进入共享 AI 抽屉 → 后台自动匹配多个方向 → Gemini 生成 → 自动质检和重试 → 用户采用、编辑、发布 → 反馈回流。

本文回答四个核心问题：

1. VibePin 为什么需要自己的参考图库，而不是只让用户写提示词。
2. 图片采集后如何审核和标注，哪些图片可以进入生成链路。
3. 用户从 Website URL、上传图片或现有图片卡开始时，系统如何自动选择参考方向并生成不同风格的社媒图片。
4. 如何保证商品不变形、位置合理、画面真实、有博主感，并通过反馈逐步提高可用率。

## 2. 背景

### 2.1 用户背景与优势

产品发起人具有景观设计和互联网产品经验，能够判断空间关系、场景搭配、构图、材质、尺度和真实生活状态。VibePin 不应成为又一个“输入一句话生成漂亮商品图”的工具，而应把这种判断沉淀为可重复使用的社媒内容系统。

### 2.2 当前用户问题

已有商品的中小卖家通常面临以下问题：

1. 有商品图，但不知道应该把商品放进什么场景、采用什么角度和表达方式。
2. Pinterest、Instagram 上有大量灵感，但搜索、筛选、判断和转化成提示词很耗时。
3. 通用 AI 出图经常过于干净、像广告大片或样板间，缺少自然流内容的生活感。
4. 同一批结果往往只是换颜色和背景，风格差异不够大。
5. 商品容易被 AI 改形、改色、改变材质、错误悬浮、穿模或放在不合理的位置。
6. 用户真正想要的是“可以直接发的社媒内容”，不是白底商品图，也不是复杂的图库搜索器。

### 2.3 产品机会

VibePin 的差异化不是“生成能力本身”，而是：

1. 持续积累多类目、经过人工判断的自然流参考库。
2. 把好图拆成场景、构图、镜头、光线、动作和生活痕迹等可执行结构。
3. 根据具体商品自动选择适合的表达方式，而不是随机套模板。
4. 一次提供结构明显不同的多个方向，帮助卖家快速找到可用表达。
5. 用商品保真锁和生成后质检控制错误，而不是把所有判断交给图片模型。
6. 记录“用户喜欢什么”和“用户实际发布什么”，但不把少量数据包装成“高转化预测”。

### 2.4 产品定位

VibePin 的核心承诺为：

> 上传已有商品，VibePin 自动参考经过筛选的自然流社媒内容，为商品生成多个真实、可发布、风格不同的内容方向，同时尽量保持商品本身不变。

不得对外承诺：

- 保证爆款、收藏量或转化率。
- 使用了专有训练模型，除非未来确实完成训练并有证据。
- 参考库中的每张图片都是“高转化图片”。收藏、互动、审美和真实转化必须分开描述。
- 生成图一定能直接发布。必须经过自动质检和用户确认。

## 3. 用户与核心任务

### 3.1 首要用户

- 已经有商品图、商品网页或现有内容卡片的中小卖家。
- 没有专职设计师，需要持续制作 Pinterest、Instagram 等图文内容。
- 愿意选择或审核结果，但不希望研究复杂提示词。

### 3.2 次要用户

- 社媒运营人员、小型代理商和多商品店铺。
- 希望上传多件商品，生成穿搭、桌面组合、礼盒或生活场景搭配的用户。

### 3.3 不作为当前主用户

- 只需要白底抠图、换背景的传统电商商品图用户。
- 需要精确 CAD、室内施工图或法律意义上完全真实展示的用户。
- 尚未选品且主要诉求是寻找蓝海商品的用户。选品属于独立产品或上游入口，不在本 PRD 内重做。

### 3.4 核心 Job To Be Done

> 当我已经有一个或多个商品时，我希望系统替我判断这些商品适合怎样出现在社媒内容里，并快速生成几种真实、不同、可使用的表达，让我不必自己找灵感、写提示词和反复试错。

## 4. 产品原则

1. **社媒内容优先。** 不把白底商品图和普通 listing 图当作主要参考方向。
2. **后台智能优先。** 默认自动选择参考结构，用户不必先浏览图库。
3. **结果可解释。** 生成后可以看到采用的内容方向和关键结构，不展示内部复杂分数。
4. **商品身份优先于审美。** 商品形状、颜色、材质、数量、功能和关键标志错误时，即使画面漂亮也必须失败。
5. **结构差异优先于调色差异。** 多方向必须改变场景结构、镜头、使用关系或内容叙事。
6. **自然真实优先。** 允许轻微杂乱、普通光线和不完美构图；不默认生成豪华大片或样板间。
7. **人工偏好与安全门禁分离。** 用户选择“要”不等于图片自动获得生成准入。
8. **缺失数据保持 unknown。** 不得把没有收藏数、发布时间或权限信息写成 0 或已验证。
9. **可回溯。** 每次采集、标注、匹配、提示词、模型调用、重试和用户决策都可追踪版本。
10. **先验证稳定性，再扩大类目。** 不以图库总数量作为进展指标。

## 5. 范围

### 5.1 本期范围

- 多类目参考图采集与候选池。
- 图片哈希与 Pin ID 去重。
- 两按钮人工审核。
- 通用字段和类目专属字段标注。
- 参考图生成准入判定。
- Website URL 分析、图片上传、现有图片卡预填和多商品组合。
- 商品身份分析与不可变属性锁定。
- 后台自动参考、三方向规划和风格卡生成。
- Gemini 图片生成。
- 生成结果自动质检、定向重试和用户审核。
- 用户采用、不要、重新生成、调整方向和发布行为回流。

### 5.2 非目标

- 不在首版训练 LoRA 或专有基础模型。
- 不把 Pinterest 素材直接作为公开模板销售。
- 不自动发布未经过用户确认的内容。
- 不在本期完成自动视频生成；视频卡不进入本 PRD 的图片生成链路，也不显示 `Create AI version`、`Regenerate image`、`重新生成图片` 或任何同义生图动作。
- 不新建与 Studio 平级的 AI 创建页面、独立 Store 或 From URL / From product / From media 三 Tab。
- 不建设与独立蓝海选品工具重复的完整选品系统。
- 不因本 PRD 直接删除现有找 Pin、趋势关键词或 Product Opportunity 底层能力；入口可逐步弱化或融入创作流程。

## 6. 名词定义

| 名词 | 定义 |
|---|---|
| 商品身份图 | 来自 URL 提取、用户上传或当前图片卡的主图片，用于确定商品外观、颜色、材质、数量和结构，是“画什么”的事实源 |
| 参考图 | 来自 Pinterest、用户上传、历史成品或其他来源，用于提取构图、场景、光线、动作和内容叙事，是“怎么拍”的依据 |
| 生成图 | 系统根据商品身份、风格配方和约束生成的社媒图片 |
| 标注 | 对图片中的可见事实、空间关系、内容结构、真实性风险和准入状态进行结构化记录 |
| 风格卡 | 可直接用于生成的结构化配置，不只是“北欧风”等名字 |
| 商品保真锁 | 生成时不可改变的商品事实和物理关系 |
| 自然流 | 看起来像普通用户、博主或品牌日常发布，而不是白底 listing、模板海报或大型广告片 |
| `direct_recipe` | 可直接提取较完整生成配方 |
| `structure_only` | 只允许借用局部抽象结构，不直接复刻画面 |
| `exclude` | 不得进入生成配方 |

## 7. 总体流程

### 7.1 后台素材供应链

```text
类目与细分方向规划
→ 多轮采集
→ 元数据完整性检查
→ Pin ID / 图片哈希去重
→ 内容与质量硬门槛
→ 用户“要 / 不要”审核
→ AI 初标
→ 规则校验与抽检
→ generation_access 判定
→ 标签、向量和风格卡入库
→ 版本化参考库
```

### 7.2 上线后的用户生成链路

```text
顶部 `Create with AI` 或图片卡 `Create AI version` 打开同一个共享抽屉
→ 从 Website URL、上传图片或当前图片卡取得主素材
→ 确认摘要、主素材、附加图片和可选参考图
→ 商品身份分析
→ 自动判断类目、场景限制和营销任务
→ 从参考库召回相关候选
→ 评分、去重与多样性重排
→ 生成三个结构不同的风格卡
→ 冻结本次生成快照
→ 立即创建 N 个 Draft 占位卡
→ Gemini 生成
→ 自动商品保真与真实感质检
→ 结果逐张回填；失败图定向重试或明确失败
→ 用户要 / 不要 / 调整方向 / 发布
→ 偏好与表现信号回流
```

## 8. 参考图采集

### 8.1 类目结构

首轮七个实体类目：

| 一级类目 | 重点细分方向 |
|---|---|
| Home | 家具、灯具、收纳、家居装饰、小空间、桌面与墙面陈设 |
| Fashion | 日常穿搭、鞋包、配饰、镜前、街拍、坐姿、多商品搭配 |
| Beauty | 护肤、彩妆、香水、头发护理、身体护理；美甲只保留少量代表样本 |
| Garden/Outdoor | 阳台、庭院、户外家具、工具使用、植物养护、户外用餐 |
| Food & Drink | 食材准备、烹饪过程、端盘、分享、家庭餐桌、饮品制作 |
| DIY & Crafts | 材料、手部制作、步骤、工具、半成品、真实工作台 |
| Wedding | 小型婚礼、后院婚礼、餐桌、迎宾区、仪式区、宾客反应、布置过程 |

长期可扩展宠物、母婴、旅行、健身、数码配件等 Pinterest 重点类目，但必须逐类建立标注和生成验收规则。

### 8.2 采集任务输入

每次采集任务必须明确：

- `category`
- `subcategory`
- `content_task`：如“阳台家具正在被使用”，而不只是“garden”
- 查询词矩阵
- 时间范围
- 最低收藏门槛
- 目标数量
- 排除词
- 本轮与历史重复索引版本
- 采集时间和执行版本

### 8.3 采集轮次

- Home、Fashion 已有有效基线时，每次补一轮增量候选。
- 新类目或不稳定类目至少三轮采集，每轮使用不同细分查询方向。
- 每轮原始候选建议 12–20 张，通过硬门槛后保留 6–10 张终审候选。
- 类目供给不足时扩展细分任务和查询词，不降低质量门槛凑数。

### 8.4 元数据

每张候选至少记录：

| 字段 | 规则 |
|---|---|
| `reference_id` | VibePin 内部稳定 ID |
| `pin_id` | Pinterest Pin ID；缺失时标记 unknown |
| `source_url` | 原始来源链接 |
| `image_url` | 原图或可审核版本地址 |
| `pin_created_at` | Pin 创建时间，不是采集时间 |
| `scraped_at` | 采集时间 |
| `save_count` | 采集时收藏数；缺失不能写 0 |
| `reaction_count` | 互动数；不能代替收藏或转化 |
| `comment_count` | 评论数；缺失保持 unknown |
| `source_keyword` | 采集查询词 |
| `image_sha256` | 下载文件哈希 |
| `width/height/mime` | 媒体信息 |
| `metadata_confidence` | 元数据可信度与来源 |

### 8.5 首轮硬门槛

用于“近期热门参考库”的候选默认要求：

1. `pin_created_at` 距采集日不超过 183 天。
2. `save_count >= 100`。
3. Pin ID 未出现在历史候选、审核或正式标注中。
4. 图片 SHA-256 未出现在历史库中。
5. 属于自然流社媒内容，而非白底商品图、纯 listing、模板文字海报或明显广告大片。
6. 无明显 AI 结构错误、严重水印、界面覆盖或无法使用的低清问题。
7. 至少包含一种可执行结构：空间、构图、镜头、光线、使用动作、搭配或内容叙事。

说明：该门槛适用于首轮建立“近期且有收藏证据”的库。未来可另建常青结构库，但必须单独标记，不能混用“近期热门”标签。

### 8.6 排除规则

- 白底单品、孤立产品 listing。
- 主要价值来自可读文字的海报或信息图。
- 明显品牌广告大片，无法转化成自然内容。
- 明显 AI 肢体、植物、家具或餐具错误。
- 无清晰主体或无法判断空间关系。
- 与类目不符，例如把衣柜收纳图当作 Fashion 穿搭参考。
- Wedding 中的婚纱、戒指、伴手礼等纯产品图。
- Beauty 中大量重复美甲图或仅包装陈列图。
- Garden 中只有景观大片、没有商品或使用关系的图片。

## 9. 人工审核

### 9.1 审核页

每个类目单独提供审核页。每张图显示：

- 图片。
- 类目和细分类目。
- Pin 创建时间。
- 收藏、互动和采集时间。
- Pinterest 来源链接。
- 系统建议的可借结构。
- 风险提示。
- “要”和“不要”两个按钮。

### 9.2 按钮规则

- 默认状态为“要”。
- 用户只需点击不需要的图片为“不要”。
- 不使用下拉框。
- 选择刷新后保留。
- 顶部实时显示“要 / 不要 / 总数”。
- “导出审核结果”生成结构化 JSON，并记录 `review_completed_at`。

### 9.3 决策含义

- 用户“要”：符合用户偏好，可以继续做正式标注。
- 用户“不要”：本批次排除，不进入标注与生成。
- 用户“要”不能绕过 AI 真实性、品牌文字、错误结构或生成准入门禁。

## 10. 结构化标注

### 10.1 标注目标

标注不是为图片写描述，而是把图片转成可以被检索、组合和执行的生成结构。

### 10.2 通用字段

| 字段组 | 主要字段 |
|---|---|
| 身份与来源 | `reference_id`、类目、细分类目、来源、哈希、审核状态、标注版本 |
| 主体 | 主体类型、商品类型、可见数量、主次层级、清晰度 |
| 空间位置 | 画面区域、前中后景、占画面比例、朝向、距离 |
| 物理关系 | 支撑面、接触点、悬挂、手持、穿戴、摆放、相邻关系 |
| 遮挡 | 遮挡程度、遮挡物、关键商品是否被遮挡 |
| 场景 | 房间/户外类型、使用状态、时间感、空间尺度 |
| 构图 | 单主体、多商品、场景型、留白、层次、视觉重心 |
| 镜头 | 远近景、视角、俯仰、手机抓拍感、景深 |
| 光线 | 光源方向、软硬、色温、曝光、阴影和混合光 |
| 配色材质 | 主色、辅色、材质、表面纹理、反光属性 |
| 生活感 | 整洁度、杂物密度、使用痕迹、不完美程度 |
| 内容叙事 | 展示、使用、步骤、搭配、问题解决、结果、分享 |
| 人物 | 无人、手部、局部、全身、动作、穿戴层级、姿态 |
| 文字与品牌 | 可读文字、品牌、平台 UI、水印、第三方 IP |
| 真实性风险 | AI 伪影、肢体、穿模、悬浮、比例、重复物、假文字 |
| 多商品关系 | 搭配、主辅、兼容、冲突、共同使用关系 |
| 生成准入 | `direct_recipe`、`structure_only`、`exclude` 及原因 |

### 10.3 类目专属字段

**Home**

- 房间和功能区。
- 家具与墙面、地面、台面支撑关系。
- 尺度和通行动线。
- 家居风格、生活痕迹和杂物类型。

**Fashion**

- 身体区域、穿戴层级、单品搭配关系。
- 姿势、镜前/街拍/坐姿/移动状态。
- 面料垂坠、鞋底接地、包的背法和首饰位置。

**Beauty**

- 护肤、彩妆、香水、头发护理或身体护理。
- 使用阶段、手部或身体部位。
- 液体、膏体、皮肤、头发等真实纹理证据。
- 功效是否只被暗示而没有实际证据。

**Garden/Outdoor**

- 阳台、庭院、草坪、花园床、户外餐区。
- 植物状态、季节、工具与人的使用关系。
- 家具接地、花盆承重、浇水和种植动作。

**Food & Drink**

- 食材、半成品、成品和制作阶段。
- 食物与容器、餐具、手部的接触关系。
- 可食用质感、蒸汽、液体和碎屑真实性。

**DIY & Crafts**

- 材料、工具、步骤、半成品和最终成品。
- 手部动作、工具接触点和步骤逻辑。
- 画面展示的是实际完成，还是只承诺结果。

**Wedding**

- 仪式、宴会、布置、宾客反应和细节。
- 正在布置、正在使用或完成后的时间阶段。
- 场地规模、桌椅关系、人群密度和真实预算感。

### 10.4 标注执行

1. AI 模型依据图像和元数据生成初标。
2. JSON Schema 校验必填字段、枚举、矛盾和空值。
3. 规则校验典型冲突，例如“无人物”却填写身体区域、“无遮挡”却列出遮挡物。
4. 每批抽检高风险和低置信度项。
5. 新 Schema 必须重新做独立样本校准，不能沿用旧版本审查结论。
6. 标注不确定时保留 `unknown`，禁止猜测。

### 10.5 标注质量门槛

- 新样本双人/双模型独立标注总体关键字段一致率建议不低于 90%。
- 每类关键字段一致率建议不低于 85%。
- 商品数量、支撑/接触、人体穿戴、品牌/IP 和生成准入为高权重字段。
- 一致率不达标时先修规则和样例，再用新样本复测；不能用人工裁决后的结果冒充独立一致率。

## 11. 参考图准入与风格卡

### 11.1 生成准入

**`direct_recipe`**

- 主体与场景清晰。
- 空间和物理关系合理。
- 可提取完整构图、镜头、光线和内容叙事。
- 无严重品牌文字、平台 UI 或复制风险。

**`structure_only`**

- 图片整体不能直接作为生成参考，但局部结构有价值。
- 只提取抽象关系，如“低机位街拍”“前景植物轻微遮挡”“桌面轻度使用痕迹”。

**`exclude`**

- 商品图、模板图、明显广告大片。
- 严重 AI 错误、物理错误、品牌文字或第三方 IP 风险。
- 无法提取可执行结构。

### 11.2 风格卡字段

### 11.3 可借与不可借

允许借用：

- 场景类型和空间关系。
- 构图、镜头距离、视角和景深。
- 光线方向、配色区间和材质组合。
- 人物动作、使用关系和内容叙事。
- 陈设密度、杂乱程度和生活痕迹。

不得复制：

- 独特人物身份、脸、姿势组合或标志性造型。
- 可读文字、商标、水印、平台 UI。
- 原图中的整套独特布景或完整画面。
- 第三方商品外观、IP 角色或受保护图案。

## 12. 上线后的用户流程

### 12.1 入口与复用边界

Studio 只保留两个进入同一图片生成能力的入口：

| 入口 | 位置 | 打开结果 | 初始上下文 |
|---|---|---|---|
| `Create with AI` | Studio 顶部 | 共享 `Create AI version` 抽屉 | 空白 Setup，Website URL 默认获得焦点；也可直接上传图片 |
| `Create AI version` | 图片卡媒体操作区 | 同一个共享抽屉 | 预填当前图片、Website URL、现有文案和 Draft ID |
| `Regenerate image` | 图片卡媒体操作区 | 复用当前图片生成链路 | 预填当前图片、原 Setup、方向和 Draft ID；不得创建第二套任务体系 |

硬规则：

1. 两个入口复用同一个现有抽屉组件、Setup schema、生成服务、额度校验、占位卡、失败恢复和审计记录。
2. 顶部入口只是全局快捷方式，不新建独立路由、独立 Store、独立计费或第二套生成状态。
3. 不使用平级的 From URL / From product / From media 三 Tab。来源差异只改变 Setup 初始值，不改变后续流程。
4. 图片卡入口不得丢失卡片上下文；当前图片、URL、文案和 Draft ID 必须一起进入 Setup。
5. 图片卡可显示 `Create AI version` 和 `Regenerate image`；后者复用同一个 Setup、生成服务、额度、占位卡、失败恢复和审计记录。
6. 无论视频来自上传、URL 抽取还是历史 Draft，视频卡都不得显示 `Create AI version`、`Regenerate image`、`重新生成图片` 或任何同义生图动作，视频也不得作为图片生成主体输入。
7. 媒体类型识别或替换完成后，必须根据标准化 `mediaType=image|video` 重新派生整套媒体动作。图片切换为视频时立即移除所有生图动作；视频切换为图片时立即移除视频封面动作，不得残留旧媒体类型的按钮、菜单项、快捷键或恢复状态。
8. `Edit cover image` 只属于视频卡，且只覆盖在视频主预览上；不得在预览下方建立独立封面缩略卡、`Choose cover frame` 大按钮或第二个封面入口。
9. 用户不需要先进入“找 Pin”或“趋势关键词”；参考图库能力在后台为共享抽屉服务。

### 12.2 URL 与图片素材确认

顶部入口支持两种起点：输入 Website URL，或直接添加图片。图片卡入口直接使用当前图片，也允许补充 URL、附加图片和参考图。

URL 流程固定为：

```text
输入 Website URL
→ Analyze URL
→ 直接展示 Page summary 与 Extracted media
→ 用户确认 Primary image、Additional images 和可选 Style references
→ 进入方向生成与编辑
```

URL 分析只负责提取本次 Setup 所需上下文：

| 类型 | 名称 | 规则 |
|---|---|---|
| 字段 | Website URL | 可选；分析时必须为完整合法 URL；保留用户原始输入 |
| 只读字段 | Page summary | 标题、主体、卖点或文章摘要；只能作为建议上下文 |
| 选择字段 | Extracted media | 多选；至少确认 1 张主图片后才可继续 |
| 选择字段 | Primary image | 单选；作为主体保真依据 |
| 选择字段 | Additional images | 可选；辅助主体一致性 |
| 选择字段 | Style references | 可选；只影响场景、构图、光线与氛围，不得改变主体事实 |
| 状态 | Idle / Analyzing / Ready | 未分析、分析中、可继续 |
| 状态 | Partial / Unsupported / Failed | 允许补充上传、改 URL 或重试 |

URL 分析结果必须直接进入摘要和素材确认区域，不新增页面类型提示卡或阻断式设置弹窗。系统可以在后台判断页面类型来优化提取，但不得要求用户离开当前抽屉完成其他配置。

重复分析同一 URL 优先复用有效结果。分析期间不得清空 Website URL、用户已确认的素材或手动编辑的字段；取消分析只终止当前请求，不清空输入。

### 12.3 默认自动模式

商品确认后，系统自动：

1. 分析商品身份。
2. 匹配参考结构。
3. 规划三个明显不同的内容方向。
4. 显示方向摘要，不要求先选参考图。

建议的三个默认方向不是固定名称，而是从以下方向族中选择：

- 真实使用/生活过程。
- 博主抓拍/人物关系。
- 搭配展示/空间陈设。
- 细节和材质特写。
- 问题解决/前后状态。
- 步骤或制作过程。

### 12.4 共享 Setup 字段、按钮与状态

生成前字段与 Studio 主 PRD 保持一致：

| 字段 | 类型 | 规则 |
|---|---|---|
| Website URL | URL | 可选；顶部入口默认聚焦；图片卡入口预填现有值 |
| Primary image | 单选图片 | 必填；来自 URL、当前图片卡或上传 |
| Additional images | 多选图片 | 可选；辅助主体一致性和多角度理解 |
| Style references | 多选图片 | 可选；不得改变主体事实 |
| Creative direction | 多行文本 | 可编辑；可从系统生成的三个方向开始 |
| Style / Scene / Composition / Mood | 选择器 | 复用当前选项，不新增平行标签系统 |
| Model | 选择器 | 复用当前可用模型 |
| Quantity | 数字选择 | 继承当前产品规则；默认先生成三个方向 |
| Aspect ratio | 选择器 | 默认 Pinterest 推荐比例 |
| Diversity | 选择器 | 控制结果之间的结构差异程度 |

按钮和状态：

| 类型 | 名称 | 规则 |
|---|---|---|
| 按钮 | `Analyze URL` | URL 合法时启用 |
| 按钮 | `Cancel analysis` | 终止当前分析，不清空 URL 或用户值 |
| 按钮 | `Retry` | URL 分析失败时只重试分析阶段 |
| 按钮 | `Add images` / `Add references` | 添加主体图或参考图 |
| 按钮 | `Remove` | 移除单张素材；不能静默改选其他主图 |
| 按钮 | `Generate directions` | 生成三个结构明显不同的方向 |
| 按钮 | `Edit direction` | 编辑选中方向，用户值成为后续生成事实源 |
| 按钮 | `Generate` | Setup 合法且额度校验通过后启用 |
| 按钮 | `Cancel generation` | 仅在提供商支持安全取消的阶段显示 |
| 按钮 | `Retry failed` | 只重试失败结果 |
| 按钮 | `Close` | 存在未保存变化时显示离开确认 |
| 状态 | Setup incomplete | 明确指出缺失字段 |
| 状态 | Generating N items | 显示总数、成功数和失败数 |
| 状态 | Partial success / Failed | 保留成功结果和完整 Setup |

### 12.5 字段所有权与 AI 建议

1. URL 摘要、图片分析和参考图库只产生建议，不拥有用户字段。
2. 只有空白且 `userTouched=false` 的标题、描述、方向等字段可以自动填入，并标记 `AI suggested`。
3. 用户已编辑或已有内容的字段不得被静默覆盖；新建议与现有值冲突时必须显示差异。
4. 应用建议必须由用户触发 `Apply this field` 或明确的批量应用操作。
5. 卡片入口预填的文案和 Draft ID 在抽屉关闭、生成失败、页面刷新和恢复后保持关联。
6. 用户编辑 Creative direction 后，最终生成必须逐字使用已保存的可见值，不能改用隐藏旧版本。

### 12.6 生成中

显示单一稳定任务状态：

- 正在分析商品。
- 正在匹配内容方向。
- `Generating N items`，显示总数、成功数和失败数。
- 正在检查商品和画面。

用户点击 `Generate` 后，系统先原子保存同一 Setup，再立即创建 N 个 Draft 占位卡；结果逐张回填。不得在后台仍运行时提前显示成功。用户关闭抽屉、刷新页面或路由切换后，任务、占位卡和 Setup 必须可恢复。

### 12.7 结果页

每张结果显示：

- 生成图。
- 方向名称，例如“朋友随手拍的街角穿搭”。
- 采用的结构摘要，例如“半身街拍、侧向自然光、鞋包同时可见”。
- “要”“不要”。
- “调整这个方向”。
- 图片卡可使用 `Regenerate image`；复用当前 Setup 和图片生成链路，不新建第二套任务。
- “编辑文字/裁切”。
- 卡片内编辑、选择发布目标、加入 Schedule Plan 或发布。

用户不需要看到具体参考 Pin；点击“为什么这样生成”时可以看到抽象依据和来源说明。

每张生成图必须保留 `AI-generated` 底层状态；用户关闭视觉标签不得删除来源记录。平台需要披露时，由发布层读取真实状态。

### 12.8 调整方向

“调整这个方向”提供高频快捷项：

- 更真实一点。
- 增加一点生活杂物。
- 不要这么整齐。
- 换一个家居/穿搭/花园风格。
- 保持商品，换场景。
- 保持场景，换角度。
- 人物更自然。
- 商品更突出。

用户也可输入补充要求。调整只重做当前方向，不重新消耗已经通过的结果。

### 12.9 与 AI 文案的边界

图片生成抽屉可以读取卡片已有标题、描述和 URL 作为上下文，但不在内部复制一套文案编辑器。标题、Description / Caption、Alt text、Keywords / Tags 和 Board recommendation 继续由 Studio 共享 `AI writing` 面板处理，并遵守以下合同：

1. `Generate copy`、`Regenerate` 只产生建议，不立即覆盖卡片字段。
2. 用户通过 `Apply this field` 或确认覆盖范围后的 `Apply all suggestions` 应用结果；`Keep current` 保留现有值。
3. Existing copy handling 必须区分 `Fill empty fields` 与 `Suggest replacements`。
4. 文案生成失败不得清空当前内容，也不得阻断图片生成和手动编辑。
5. 图片卡进入 `Create AI version` 时，当前文案只作为预填上下文；从共享抽屉返回时不得把旧快照写回覆盖用户期间的新编辑。

### 12.10 视频封面与服务端保存边界

视频封面不属于 AI 图片生成，但与媒体动作互斥，必须遵守以下边界：

1. `Edit cover image` 只覆盖在视频主预览底部；桌面 hover / focus 时显示，移动端持续可见。
2. 视频主预览下方不得出现独立封面缩略卡、`Media · 1` 封面卡、`Choose cover frame` 大按钮或第二个封面入口。
3. 保存后的封面必须在卡片、Schedule Plan、发布确认和最终 provider payload 中一致。
4. 抽帧或封面保存失败时保留原视频与原封面，只显示该阶段的 `Retry`，不得出现图片生成动作。

Draft、生成 Setup、占位卡和 History 的保存状态以登录账号及 workspace 的服务端事实源为准：

| 状态/入口 | 规则 |
|---|---|
| `Saving…` | 正在写入服务端 Draft，不得提前显示成功 |
| `Saved` / `已保存` | 仅服务端确认成功后显示 |
| `Waiting to sync` / `等待同步` | 离线或网络失败；本地仅缓存待同步操作，不是最终事实源 |
| `History` / `历史记录` | 查询当前登录账号与 workspace 的服务端记录 |

界面不得显示 `Saved to this device`、`已储存到这台装置` 或任何同义提示。同一账号可在另一台设备恢复相同 workspace 的 Draft、生成任务与 History；不同账号和 workspace 不得串读。

## 13. 商品身份分析与保真锁

### 13.1 商品分析字段

| 字段 | 说明 |
|---|---|
| `product_id` | 稳定商品 ID |
| `category/subcategory` | 商品类目和细分类目 |
| `product_count` | 需要出现的准确数量 |

- 商品数量。

- 主色和关键材质。
- 真实功能。
- 标志性设计特征。

### 13.3 商品信息不足

- 看不清结构时提示用户补充角度，而不是猜。
- 多张图互相冲突时暂停生成并让用户确认主图。
- 不能识别品牌文字时，默认禁止生成可读文字，避免假字和伪造品牌。

## 14. 后台自动推荐算法

### 14.1 算法目标

算法不是寻找“最像商品的图片”，而是寻找：

> 与商品和内容任务兼容、能提供可执行结构、真实感足够，并且彼此差异明显的参考组合。

### 14.2 第一步：硬过滤

候选必须满足：

- 类目或兼容类目匹配。
- `generation_access` 为 `direct_recipe` 或 `structure_only`。
- 用户未明确不要。
- 参考记录与图片哈希有效。
- 无严重商品图、文字、品牌、AI、物理和低清风险。
- 适用于当前商品数量、人物要求和内容目标。

### 14.3 第二步：多路召回

并行召回最多约 60 条候选：

1. **结构化标签召回：** 类目、场景、构图、使用关系、人物和营销任务。
2. **图文向量召回：** 商品图视觉向量＋商品标题/描述文本向量。
3. **内容任务召回：** 例如“户外灯在晚间真实庭院中使用”，而不是只搜“灯”。
4. **用户历史召回：** 用户自己曾采用或发布的风格；首版数据不足时不启用自动个性化。

### 14.4 第三步：候选评分

建议目标评分为 0–100：

```text
candidate_score =
  30% 商品/任务语义相关度
  20% 类目与细分类目兼容度
  15% 物理与使用关系兼容度
  10% 构图和镜头可执行度
  10% 参考图质量与真实感
   5% 收藏证据（对数归一化）
   5% 新鲜度
   5% 用户历史偏好（有足够样本才启用）
  - 风险罚分
```

风险罚分包括：文字/IP、商品图倾向、明显广告感、AI 伪影、结构不完整、低清和元数据不可信。

业务规则：

- 收藏数只能作为弱信号，不能把不相关图片推到前面。
- 没有收藏数时不是 0 收藏，只是该维度不参与，并降低证据置信度。
- 用户偏好样本少于 10 次有效决策时，不启用个性化加权。
- 前台不显示内部总分，避免伪造精确性。

### 14.5 第四步：多样性重排

从高分候选中选择三个方向时使用 MMR/相似度惩罚思路：

```text
direction_value = candidate_score
                  - 0.35 × 与已选方向的结构相似度
                  - 0.20 × 与已选方向的场景相似度
```

三个方向至少在以下维度中的两个发生变化：

- 场景结构。
- 镜头距离或角度。
- 人物/手部参与方式。
- 商品使用关系。
- 内容叙事。
- 光线时间。

只有调色、换墙色或更换小道具不算新方向。

### 14.6 第五步：参考融合

每个方向可以组合：

- 1 张主要结构参考。
- 0–2 张局部参考，分别提供光线、杂乱度或人物动作。
- 1 套类目 Playbook。
- 1 套商品保真锁。

参考冲突时优先级：

```text
商品事实 > 物理安全与真实性 > 用户明确要求 > 主要结构参考 > 局部参考 > 类目默认风格
```

## 15. 风格配方与提示词组装

### 15.1 提示词层次

最终提示词按固定顺序组装：

1. 输出任务：生成一张原始、真实的竖版社媒图。
2. 商品身份源说明。
3. 商品不可变锁。
4. 场景和内容叙事。
5. 商品与人物/空间的位置关系。
6. 镜头、构图和光线。
7. 可控生活痕迹和杂物。
8. 参考结构说明。
9. 禁止项。
10. 输出规格。

### 15.2 真实生活感规则

默认不是“越乱越真实”，而是加入 2–4 个有因果关系的生活痕迹：

- 杯子、书、毛巾、电线、鞋、工具、包装或碎屑。
- 必须与场景和人物行为有关。
- 不生成垃圾、污渍、危险摆放或完全随机的幽灵物件。
- 轻微曝光偏差、普通阴影和不完全对称可以保留。

### 15.3 类目示例

**Home：** 同一台灯可分别生成“普通出租屋阅读角”“色彩后现代客厅”“晚间侘寂卧室”，但台灯弧度、灯罩颜色、底座和支撑不变。

**Fashion：** 同一套商品可分别生成“镜前试穿”“朋友街角抓拍”“咖啡店坐姿”，服装层级、鞋包和首饰位置正确。

**Beauty：** 同一香水可分别生成“梳妆台晨间使用”“包中随身物品”“手腕喷香后的生活片段”，不虚构功效。

## 16. 图片生成

### 16.1 模型策略

- 正式图片生成优先使用 Gemini 图片模型。
- 批量标注和机械视觉审查可使用 Gemini Flash 系列。
- 不得在 Gemini 不可用时静默换成其他图片模型并冒充同一结果。
- 模型、提供商、模型版本和调用时间必须记录。

### 16.2 输入顺序

多模态输入顺序固定：

1. 商品身份图，按主商品到辅商品排列。
2. 经准入允许的参考图或结构化参考配方。
3. 完整生成提示词。

每个输入明确 `role=product_identity` 或 `role=composition_reference`，不得混淆。

### 16.3 默认输出

- 竖版优先，首选 2:3；模型仅稳定支持 3:4 时允许生成后裁切，但不得裁掉关键商品。
- 默认 3 个结构不同的方向，每个方向先生成 1 张。
- 用户选择方向后，再扩展相似版本，避免一开始生成大量无效图片。
- 实际输出数量由共享 Setup 的 `Quantity` 决定；开始生成后立即创建相同数量的 Draft 占位卡，并逐张回填结果。
- `Diversity` 控制方向之间的结构差异，不得通过另建生成入口或第二套参数状态实现。

### 16.4 任务快照

每次生成必须冻结并保存：

- 用户、workspace、共享 Setup、generation intent ID；图片卡入口同时保存来源 Draft ID。
- Website URL、Page summary 的来源版本，以及用户确认的 Primary image / Additional images / Style references。
- 商品 ID、输入图地址和 SHA-256。
- 商品保真锁。
- 参考 ID 和风格卡。
- 用户可见 Creative direction、Style / Scene / Composition / Mood 和完整提示词版本。
- Model、Quantity、Aspect ratio、Diversity、提供商和输出规格。
- 用户字段的 `userTouched` / suggestion 状态，保证恢复时不静默覆盖。
- 输出地址、SHA-256、时长和状态。

## 17. 自动质检与重试

### 17.1 质检维度

每张生成图至少检查：

| 维度 | 关键判断 |
|---|---|
| 商品身份 | 数量、轮廓、颜色、材质、关键部件和功能是否保留 |
| 位置关系 | 是否放错位置、悬浮、穿模、错误挂墙或错误穿戴 |
| 尺度 | 商品与人、家具、桌面和空间比例是否合理 |
| 遮挡 | 关键特征是否被过度遮挡 |
| 人体 | 手、脚、关节、穿衣层级和握持是否自然 |
| 真实感 | 是否有塑料感、样板间感、幽灵物件、重复物或假光影 |
| 自然流 | 是否像社媒日常内容，而不是白底图或豪华广告大片 |
| 差异性 | 与同批方向是否只是换色 |
| 文字品牌 | 是否出现假字、伪造标志、第三方品牌或水印 |
| 安全 | 是否出现危险或错误使用方式 |

### 17.2 结果分级

- `PASS`：可以展示给用户。
- `REWORK`：存在可定位问题，只重做该方向。
- `QUARANTINE`：商品身份或输入证据不清，暂不展示，需人工检查。
- `REJECT`：严重商品错误、危险关系、品牌伪造或明显假图。

### 17.3 定向重试

重试提示词必须包含：

- 保留哪些正确部分。
- 具体失败点。
- 只修复什么。
- 不得改变哪些商品事实。

同一方向最多自动重试 2 次。仍失败时：

- 隐藏该方向。
- 返回可用方向。
- 记录失败原因。
- 不让失败方向拖累已通过方向。

### 17.4 上线门槛

类目被标记为稳定需同时满足：

- 商品身份保真通过率不低于 90%。
- 严重支撑、接触、穿戴错误为 0。
- 明显假图、幽灵物件或肢体错误不高于 10%。
- 三个方向存在清晰结构差异。
- 用户保留率不低于 70%。
- 连续两轮达到上述标准。

任何严重商品身份错误、危险使用关系或伪造品牌文字均使该轮失败，不能用平均分抵消。

## 18. 用户反馈与学习闭环

### 18.1 记录的行为

- `reference_kept/rejected`
- `generation_kept/rejected`
- `direction_adjusted`
- `generation_retried`
- `draft_edited`
- `draft_scheduled`
- `draft_published`
- 发布后 Pinterest 返回的 saves、clicks、impressions 等真实观测

### 18.2 两类信号不得混淆

- **采纳信号：** 用户是否保留、编辑、排期和发布，反映用户偏好与可用性。
- **表现信号：** 已发布内容的收藏、点击等，反映已发布样本的受众反应。

不能因为一张图被用户选中就说它会高转化，也不能因为未发布图没有表现数据就记为 0。

### 18.3 个性化启用条件

- 少于 10 次有效用户决策：只记录，不自动改权重。
- 10–29 次：可显示“根据你最近选择的内容”，但只做轻量重排。
- 30 次以上且跨多个商品：可对场景、人物、真实感和构图做时间衰减偏好。
- 用户可随时查看、关闭或重置偏好。
- 用户自己的历史成品优先作为个性化参考；第三方参考库不用于训练个人模型。

### 18.4 时间衰减

用户偏好建议采用 90 天滑动窗口，近期行为权重大于旧行为，避免把用户锁在过去的品牌风格中。

## 19. 数据模型建议

| 表/对象 | 作用 |
|---|---|
| `reference_sources` | 来源 Pin、原始链接、时间、收藏、采集证据 |
| `reference_assets` | 图片文件、缩略图、哈希、尺寸和存储状态 |
| `reference_reviews` | 用户“要/不要”、时间和批次 |
| `reference_annotations` | 版本化结构化标注 |
| `reference_embeddings` | 图像和文本向量 |
| `style_recipes` | 可执行风格卡与准入状态 |
| `product_identity_profiles` | 商品分析和不可变锁 |
| 共享 generation Setup | 两个入口共用的生成配置快照；优先复用当前 Setup schema 和 Store，不创建平行状态 |
| `generation_jobs` | 后台任务和状态 |
| `generation_outputs` | 每张生成图、对应 Draft 占位卡、哈希、模型和质检结论 |
| `creative_feedback_events` | 要/不要、编辑、采用、发布等事件 |
| `metric_observations` | 发布后的真实平台指标与观测时间 |

业务约束：

- 原始记录不可被后续模型结果覆盖，应新增版本。
- 所有表按 workspace/user 做 owner 隔离。
- 图片放对象存储，数据库存路径、哈希和元数据。
- 标注、配方、提示词、模型和质检均带版本号。
- Website URL、来源 Draft ID、卡片文案、用户编辑状态与生成 Setup 必须使用同一 owner-scoped 快照恢复。
- Draft 与 History 由账号和 workspace 隔离的服务端记录确认；设备缓存只保存待同步操作，不得充当已保存事实源。
- 标准化 `mediaType` 是卡片动作集合的输入事实；媒体替换后必须重新派生动作，不能恢复旧类型专属按钮。
- 生产写入必须由正式迁移和 RLS 审查单独批准；本 PRD 不授权直接改生产库。

## 20. 任务状态与失败恢复

### 20.1 后台状态

```text
created
→ product_analyzing
→ reference_retrieving
→ direction_planning
→ generating
→ quality_checking
→ completed | partial | failed | cancelled
```

### 20.2 业务规则

- 同一个 intent 重放必须返回原任务，不重复扣费。
- `partial` 表示至少一张成功、至少一张失败。
- 未确认提供商是否接收任务时显示“确认结果中”，不新建重复任务。
- `Retry failed` 只重试失败方向，并保留已经成功的 Draft 卡片。
- 页面关闭、刷新或路由切换后可恢复当前任务、共享 Setup、来源 Draft 关联、占位卡和结果。
- URL 分析失败只重试 URL 分析；不得重新上传已成功素材或清空用户编辑。
- 用户点击生成后，N 个占位卡必须在提供商结果返回前创建；部分失败时保留成功回填和失败占位状态。
- 只有服务端确认 Draft 写入后才显示 `Saved`；写入中显示 `Saving…`，离线或失败显示 `Waiting to sync`。
- `Regenerate image` 仅对标准化 `mediaType=image` 可用，并复用原生成链路；切换为视频后必须立即移除。
- `Edit cover image` 仅对标准化 `mediaType=video` 可用，并只位于视频主预览覆盖层；切换为图片后必须立即移除。
- 429 遵守 `Retry-After`，倒计时前不可重复提交。

## 22. 指标

### 22.1 供应链指标

- 采集候选通过硬门槛比例。
- Pin ID 和图片哈希重复率。
- 元数据完整率。
- 用户参考图保留率。
- 标注一致率。
- `direct_recipe / structure_only / exclude` 分布。
- 每类可执行结构覆盖数。

### 22.2 生成指标

- 首次生成 PASS 率。
- 商品身份保真率。
- 严重物理错误率。
- 自动重试率和重试成功率。
- 三方向结构差异达标率。
- 用户保留率。
- 从商品确认到首批结果的时间。
- 每张用户保留图的实际模型成本。

### 22.3 产品价值指标

- 生成结果被采用、编辑、排期和发布的比例。
- 用户提交第二个商品的比例。
- 同一用户 7/30 天再次生成率。
- 制作一张可发布内容的时间是否低于用户原流程。

Pinterest 表现指标属于后续观测，不作为首轮生成质量的唯一判定标准。

## 23. MVP

### 23.1 MVP 范围

第一阶段优先上线 Home，并保留 Fashion 作为第二个验证类目：

1. 用户从 Website URL、上传图片或现有图片卡进入同一个 `Create AI version` 抽屉，并确认 1 张主图片及可选附加图片。
2. 系统生成商品身份锁。
3. 后台从已审核参考库匹配三个方向。
4. Gemini 每个方向生成一张。
5. 原子保存共享 Setup，并创建对应 Draft 占位卡。
6. 自动质检，结果逐张回填；失败项保留明确状态并可单独重试。
7. 用户进行“要/不要”、调整当前方向、加入计划或发布。
8. 保存完整任务快照、来源 Draft 关联和反馈。

### 23.2 MVP 不做

- 不做自动视频。
- 视频卡不显示 `Create AI version`、`Regenerate image`、`重新生成图片` 或任何同义生图动作，不进入图片生成链路。
- 不在视频主预览下方建立独立封面缩略卡或第二个封面入口。
- 不做模型微调。
- 不对外显示预测转化率。
- 不同时开放所有类目。
- 不在前台提供复杂参考图库搜索器。
- 不增加 From URL / From product / From media 三 Tab。

### 23.3 MVP 验收

- 至少两个类目连续两轮满足稳定标准。
- 顶部和图片卡入口复用同一抽屉、Setup、生成服务、额度、占位卡和失败恢复。
- 顶部入口可从 Website URL 或上传图片开始；图片卡入口正确预填当前图片、URL、文案和 Draft ID。
- 用户无需选参考图即可完成生成。
- URL 分析结果直接进入摘要和素材确认，不出现额外页面类型提示卡或设置弹窗，用户始终留在共享抽屉内。
- 图片卡可显示 `Create AI version` 和 `Regenerate image`，且两者复用现有 Setup 与生成任务体系。
- 视频卡在所有来源下均不显示任何 AI 生图或重新生图动作。
- 图片与视频互相替换后，动作集合立即按 `mediaType` 切换，不残留旧按钮或状态。
- 视频封面入口只覆盖在主视频预览上，下方无独立封面缩略卡或大按钮。
- 同一商品三张图在结构上明显不同。
- 商品身份保真率不低于 90%。
- 用户保留率不低于 70%。
- 失败方向可单独重试且不重复扣费。
- 刷新页面后可恢复生成任务、共享 Setup、Draft 占位卡和结果。
- 用户编辑的文案和 Creative direction 不被 URL 分析或 AI 建议静默覆盖。
- 页面不出现“已储存到这台装置”；`Saved` 只在服务端确认后显示，失败或离线显示 `Waiting to sync`。
- 同账号跨设备可恢复同一 workspace 的 Draft 与 History，不同账号和 workspace 不串数据。
- 每张图能追溯商品、参考、配方、提示词、模型和质检记录。

## 26. 停止条件

出现以下情况时暂停扩类或继续烧图：

- 某类目连续三轮商品保真或真实感仍不达标。
- 用户保留率持续低于 50%，且问题不能通过配方或提示词修复。
- 参考图供给不足，只能靠降低门槛凑数。
- 标注关键字段一致率低于门槛。
- 模型经两次定向重试仍重复产生同类严重错误。
- 单张用户保留图成本超过可接受价格，且无法通过减少重试解决。
- 数据不足却开始对外宣称“高表现”“高转化”或“为你的受众优化”。

暂停后输出明确原因：参考库问题、商品输入问题、配方问题、模型能力问题、成本问题或用户需求问题。

## 27. 最终产品判断

该方向具备明确差异化，但差异化不来自“拥有很多图片”，而来自以下闭环：

> 人工策展的自然流参考 → 可执行结构标注 → 针对商品自动匹配 → 多方向真实生成 → 商品保真质检 → 用户采用和发布反馈。

首版应让用户感觉：

1. 我只需要给商品，不需要自己研究 Pinterest。
2. 系统确实给了几个不同的内容想法，而不是同一模板换色。
3. 商品没有被改坏，放置和穿戴关系合理。
4. 图不像白底商品图，也不像昂贵广告大片，更像真实博主或普通品牌会发的内容。
5. 我可以快速保留、否决或调整一个方向，不需要重新开始。

只有当这五点能够在多个商品和连续批次中稳定成立，VibePin 的参考图库和标注体系才真正形成产品价值。
