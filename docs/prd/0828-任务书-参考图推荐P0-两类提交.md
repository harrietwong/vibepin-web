## 1. 接口合同（双方各自按此实现，不得私改）

### 1.1 `POST /api/reference-candidates` 请求体（在现有 `category / imageAnalysis / product / limit` 之上新增）

```ts
draftId?: string;                              // 有草稿时带上，事件 draft_id 用
requestId: string;                             // 客户端 crypto.randomUUID()
imageKey?: string;                             // 主商品图 URL 的 sha-256 hex 前 16 位（SubtleCrypto；不可用时 djb2 hex）
analysisSource: "draft" | "stateless" | "none"; // imageAnalysis 来自草稿 / 换图路径无状态分析 / 没有
analysisStatus: "ready" | "pending" | "failed" | "none";
seed?: string;                                 // `${draftId ?? imageKey}:${YYYY-MM-DD(UTC)}`，同一天稳定
excludeIds?: string[];                         // ≤ 72（超出服务端截断），已展示 + 已选，排序前排除
```

### 1.2 响应（在现有 `items / itemCount / source / recommendationBasis` 之上新增）

```ts
served: {
  requestId: string;
  categoryInput: string | null;                // 原样
  categoryCanonical: "fashion" | "home-decor" | "beauty" | "digital-products" | null;
  poolMode: "single" | "merged-fashion" | "unknown-roundrobin";
  poolSize: number;                            // 取样后参与排序的行数
  poolHash: string;                            // 取样池 id 排序后的短哈希（16 hex）
  excludedCount: number;
  tier1Count: number;
  tier2Count: number;
  ids: string[];                               // 返回项 id，按序
  recommendationBasis: RecommendationBasis;    // 与顶层同值，事件里按它统计 fallback 占比
}
```

`items` 元素结构不变（`ReferenceRecommendation`）。`recommendationBasis` 语义不变。

**服务端对 §1.1 所有新字段一律按可选处理、给安全默认**：`analysisSource ?? "none"`、`analysisStatus ?? "none"`、缺 `requestId` 则服务端自生成、缺 `seed` 用 `${canonical}:${YYYY-MM-DD}`、`excludeIds` 非数组视为空。客户端应当都发，服务端不得强制——旧客户端与现有测试夹具不能因此失效。

### 1.3 服务端事件 `reference_recs_served`（best-effort，失败静默）

通过 `recordAnalyticsEvents(request, [{ event_name: "reference_recs_served", draft_id, payload }])` 写入 `analytics_events`；
payload = `served` 全部字段 + `{ analysisSource, analysisStatus, imageKey, hasImageAnalysis, hasMeaningfulTitle, seedPresent, limit }`。
未登录（同源会话解析不到 userId）→ 不写、不报错。返回 `served` 与写事件互不依赖。

## 2. Agent B 细则

1. **`lib/server/recordEvent.ts`**：`export async function recordAnalyticsEvents(req: Request, rows: Array<{ event_name: string; draft_id?: string | null; payload?: Record<string, unknown> }>): Promise<void>`。内部用 `getUserIdFromSameOriginSession(req)`（`lib/server/authUser.ts`）与 `normalizeAnalyticsEvents`（`lib/analyticsIngest.ts`）；缺表错误静默（复用 events 路由现有 `isMissingTableError` 逻辑，抽到同一文件）；**永不 throw**。`/api/analytics/events/route.ts` 改为调用它，行为不变（永远 204）。
2. **`lib/studio/referenceCategory.ts`**：`canonicalizeCategory(raw) → { canonical, dbCategories }`。映射：`womens-fashion → fashion`（dbCategories = ["fashion","womens-fashion"]）；vision 同义：lifestyle / kitchen / furniture / garden / living-room / bedroom / home / interior → home-decor；jewelry / accessories / shoes / bags / mens-fashion / clothing / apparel / outfit → fashion；nails / hair / skincare / makeup / cosmetics → beauty；marketing / business / technology / education / printables / digital / templates → digital-products；四个 P0 名本身 → 自身。其它 → `{ canonical: null, dbCategories: [] }`。现有 `inferP0Category` 保留为文本兜底（其输出再过一次 canonicalize）。
3. **`lib/studio/referencePool.ts`**：`stratifiedSample(rows, { size, seed, now, tiersDays = [7, 30] })`：按 `scrapedAt` 分三层（≤7d / ≤30d / 更早），配额按层大小比例，但 ≤7d 层至少 20%、≤30d 层至少 30%（层内不足则让给其它层）；层内用 seeded PRNG（fnv1a 字符串→种子，mulberry32）无放回抽样；输出顺序确定（按 quality desc、scrapedAt desc、id asc）。`now` 必须注入，禁止在函数内 `Date.now()`。另导出 `poolHash(ids: string[]): string`（排序后 fnv1a 64 位 → 16 hex）。
4. **route.ts POST**：
   - 解析新字段；`excludeIds` 截到 72；
   - 类目：`canonical = canonicalizeCategory(body.category ?? analysis.category) ?? canonicalizeCategory(inferP0Category(text))`；
   - 取池：canonical 非空 → 按 `dbCategories` 查（`.in(...)`）`order reference_quality_score desc nullslast limit 1000`，`SELECT_COLS` 加 `scraped_at`；`stratifiedSample` 取 300（seed = body.seed ?? `${canonical}:${YYYY-MM-DD}`）；排除 excludeIds；**评分前把 row.category 归一为 canonical**（合池时 womens-fashion 行也记 fashion），input.category = canonical；`poolMode = dbCategories.length > 1 ? "merged-fashion" : "single"`；
   - canonical 为空（unknown）→ 四个 P0 类各查 250、各取样 100，**各自**调用 `rankReferencesTiered(rows_c, { ...input, category: c }, 0)`，再路由层合并：先 round-robin 各类的 Tier-1（按各自顺序交错），再 round-robin 各类的 Tier-2，去重后截 `limit`；`poolMode = "unknown-roundrobin"`；basis 用 `deriveRecommendationBasis` 对合并结果算；
   - 组装 `served`，`recordAnalyticsEvents(request, …)` best-effort；
   - GET 路径不动。
5. **referenceScoring.ts（最小、可加性改动）**：
   - `ReferenceCandidateRow.scrapedAt?: string | null`；
   - tie-break：`byIdAsc` → `byScrapedAtDescThenIdAsc`（null 视为最旧）；
   - `rankReferencesTiered(rows, input, limit, opts?: { keywordClusterCap?: number })`：簇键 = `distinctiveWords(sourceKeyword).map(normalizeWord)` 去重排序 join（空 keyword 不参与计数）；先在 Tier-1 排序结果里按簇 ≤ cap 取，溢出的 Tier-1 放到 Tier-2（同样按簇 ≤ cap）之后，再放 Tier-2 溢出；默认 cap = 2（route 传 2；不传则 undefined = 不限，保持旧行为）；`recommendationTier` 不变，basis 不受影响；
   - 现有导出、`toRecommendation` 行为不变。
6. **测试**：现有 `test-reference-scoring.ts`（13）/ `test-reference-basis.ts`（22）全绿并新增：scrapedAt tie-break、簇限流（含 "back to school outfit inspo" 与 "back 2 school outfits" 同簇）、限流不改变 basis、溢出回填；新 `test-reference-category.ts`（映射、womens-fashion 合并、unknown）、`test-reference-pool.ts`（分层配额、固定 seed 确定性、不同 seed 不同、注入时钟、poolHash 稳定）。新脚本加进 `test-registry.ts` CORE。
