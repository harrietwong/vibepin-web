# 0905 VibePin 统一 Preview 人工验收用例 v1.0

## 1. 本轮验收对象

- 稳定测试地址：`https://vibepin-fb-preview.vercel.app`
- 精确部署：`dpl_27A9yrSdynUiG3DDw2b7Z94sTr1f`
- 精确代码：`e5da25472a0aff8e8ed2b5bab9334d3a829f8def`
- 验收范围：Create Pin 历史异常图片兜底、排期/发布按钮层级、Pricing 多语言与响应式、登录态表头安全显示。
- 不在本轮验收范围：真实付款、真实渠道发布、Production、生产数据库写入、强制消耗额度、Product Opportunities 非空数据。

## 2. 验收前准备

1. 使用 Preview 测试账号登录。
2. 打开浏览器开发者工具 Console；每完成一个模块记录一次红色 error 数量。
3. 桌面轮使用 1440×900 左右窗口；移动轮使用 390×844。
4. 不点击真正的发布、删除、OAuth 重新授权或付款确认。
5. 每个失败项记录页面 URL、操作步骤、预期、实际和截图。

## 3. 第一轮：桌面验收

### P-01 Pricing 四套餐与金额

1. 打开 `/pricing`。
2. 检查四张卡：Free `$0`、Starter `$19/月`、Pro `$49/月`、Business `$99/月`。
3. 切换“按年”，检查 Starter `$15/月`、Pro `$39/月`、Business `$79/月`。
4. 检查比较表中的价格随按月/按年同步变化。

通过标准：卡片和比较表一致；无 TikTok；支持平台仅出现 Pinterest、Instagram、Facebook Page。

### P-02 Pricing 简体中文完整切换

1. 右上角语言切为“简体中文”。
2. 从页面顶部一直滚动到底部。
3. 检查导航、标题、四张套餐卡、比较表、企业方案、FAQ、底部 CTA、页脚均为中文。
4. 特别检查比较表：应显示“每月 5 / 每月 150 / 每月 300 / 不限量”等中文额度，不应残留 `/ month` 或 `Unlimited`。

通过标准：整页没有同一模块中英混排；品牌名和平台名可保留英文。

### P-03 Pricing 繁体中文完整切换

1. 将语言切为“繁體中文”。
2. 重复 P-02 的全页检查。

通过标准：套餐、比较表、FAQ、页脚完整使用繁体；额度显示“每月 n”和“不限量”。

### P-04 Pricing 登录态表头

1. 已登录状态打开 `/pricing`。
2. 检查右上角不应同时出现“登录”和“创建 Pin”。
3. 退出登录后重新打开 `/pricing`，检查“登录”和“开始使用”恢复。

通过标准：表头与真实登录态一致；旧 Cookie 不能直接授权结账。

注意：此用例只检查显示，不点击付费 CTA。

### C-01 Create Pin 历史粉色兜底

1. 打开 `/app/studio?filter=failed&sub=all`。
2. 找到历史上曾显示成整块粉色的失败卡。
3. 检查现在显示为深灰、轻微渐变/光晕的中性兜底，并有“生成失败”或“图片不可用”语义。
4. 同时检查正常人物、家居、商品图片仍正常显示。

通过标准：没有整块粉色兜底；正常图片没有被误判为兜底。

### C-02 失败卡状态与操作

1. 在失败筛选中检查“发布失败”和“生成失败”卡。
2. 检查卡片只显示与真实状态一致的标签。
3. 检查每张卡只有一处明确“编辑”入口，不出现语义重复的两个 Edit。
4. 不执行重试或发布，只检查按钮和提示。

通过标准：状态不矛盾；不存在“Posted”卡混入失败筛选；操作入口不重复。

### C-03 排期优先级

1. 找到同时有“排期”和“发布”的草稿/失败卡。
2. 检查“排期”为粉紫渐变主按钮。
3. 检查“发布”为深色/边框次按钮。

通过标准：视觉重点是排期，不是立即发布。

### C-04 失败提示轻量化

1. 打开一个缺少发布目标的确认窗口，但不要提交。
2. 检查提示是否简洁指出缺少哪个字段。
3. 检查必须字段和 Board/账号选择不被藏在 Details 中。
4. 关闭窗口。

通过标准：提示短、可操作；关闭不产生发布或排期副作用。

### C-05 Studio 页面与滚动

1. 打开草稿页并展开发布目标/详情区域。
2. 向下滚动到卡片底部。

通过标准：页面可继续下拉，所有未填写字段和底部按钮都能看到；没有滚动锁死。

## 4. 第二轮：移动端 390×844

### M-01 Pricing 响应式

1. 在 390×844 打开 `/pricing`。
2. 分别检查简体和繁体。
3. 从顶部滚动到底部。

通过标准：没有水平滚动条；套餐卡为单列；表头、语言、主题和 CTA 可操作；文字不被裁断。

### M-02 Create Pin 响应式

1. 在 390×844 打开 `/app/studio?filter=failed&sub=all`。
2. 检查顶部筛选、卡片、失败标签、排期/发布按钮和计划入口。
3. 向下滚动到深灰兜底卡。

通过标准：没有水平滚动条；卡片内容可达；深灰兜底不退回粉色；主次按钮关系不变。

## 5. Console 与结果记录

### E-01 Console

1. 分别在 Pricing 桌面、Pricing 390、Studio 桌面、Studio 390 查看 Console。

通过标准：0 条红色 error。非致命第三方 warning 单独记录，不直接判定产品失败。

### E-02 零副作用确认

本轮不得产生以下结果：

- 真实付款或订阅变化。
- 新的 Provider 发布记录、远端 Pin ID 或 permalink。
- 新的排期、删除、OAuth 重新授权。
- 额度扣减或账号套餐变更。
- Production 环境或数据库改动。
