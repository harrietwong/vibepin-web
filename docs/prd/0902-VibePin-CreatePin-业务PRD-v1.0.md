# VibePin Create Pin 生产阻断业务需求文档 v1.0

> 日期：2026-09-02
> 
> 类型：**业务需求文档（Product Requirements）**
> 
> 目标读者：产品经理、项目经理、业务方
> 
> 状态：`PRODUCTION BLOCKED` → 待开发

---

## 1. 产品愿景

让用户从"选来源"到"生成、编辑、排期、发布"始终操作同一条可追踪的 Content。用户在 Studio 中获得流畅、一致、可信赖的创作体验，所有操作都有明确的反馈，失败可恢复，状态始终透明。

---

## 2. 业务背景

### 2.1 当前问题

基于 2026-09-01 用户验收反馈，以下问题阻碍产品进入生产：

| 问题分类 | 具体表现 | 用户影响 |
|---------|---------|---------|
| **创建体验不统一** | 上传、URL、商品、AI 各有独立入口 | 用户不知道从哪开始 |
| **生成反馈混乱** | "正在生成"和"未生成任何 Pin"同时出现 | 用户困惑发生了什么 |
| **发布目标不清** | 卡片显示 Board 但实际未保存发布目标 | 用户以为能发布，实际不行 |
| **草稿同步失败** | 一个草稿出错阻断整批 | 用户不知道哪些成功哪些失败 |
| **选品体验差** | 错误信息无法定位问题 | 用户无法自助解决 |
| **移动端体验差** | 卡片过大、文字溢出、按钮挤在一起 | 用户无法在手机上工作 |

### 2.2 用户故事

**作为创作者，我希望：**
1. 从统一的入口选择图片（上传/URL/商品/AI），不用担心走错路
2. 清楚知道 AI 正在生成几张图、几张成功、几张失败
3. 选择发布目标后，能看到真实的账号和 Board，而不是模糊的提示
4. 批量编辑时，一个草稿的问题不会影响其他草稿
5. 选品灵感加载失败时，能知道是登录问题还是服务问题
6. 在手机上也能完整使用所有功能

---

## 3. 功能需求

### 3.1 统一创建入口

**需求描述**：用户只需一个"创建 Pin"入口，所有来源（上传、URL、商品、AI）都进入同一个创作流程。

**用户可见变化**：
- 桌面：一个大按钮"添加内容"，点击后展示所有来源选项
- 移动：底部 action sheet，包含所有来源

**验收标准**：
- [ ] 上传图片后可以继续选择 AI 生成
- [ ] 从商品选择后可以换图片
- [ ] 所有入口使用同一套状态管理

**优先级**：P1

---

### 3.2 商品来源展示

**需求描述**：商品来源使用用户能理解的词汇，展示真实的来源信息。

**来源文案对照**：

| 实际来源 | 用户看到 |
|---------|---------|
| user_upload | 我的上传 |
| url_import | URL 导入 |
| shopify | Shopify |
| amazon | Amazon |
| product_opportunity | 选品机会 |
| community_inspiration | 社区灵感 |

**验收标准**：
- [ ] 不显示 `Uploaded`、`Product Ideas` 等内部词
- [ ] 中英简繁三语言一致
- [ ] 每个来源配有图标

**优先级**：P1

---

### 3.3 图片加载状态

**需求描述**：所有图片加载使用统一的视觉语言，失败时用户能理解发生了什么。

**状态展示**：

| 场景 | 显示 |
|------|------|
| 加载中 | spinner（有限时，超时显示 fallback） |
| 加载成功 | 正常图片 |
| 加载失败 | 深灰色占位图 + 中性图标 |
| 生成失败 | 深灰色占位图 + 中性图标 |

**禁止**：
- 红色、粉色、紫色背景
- 乱码文字
- 永久 spinner
- `No image` 等英文

**验收标准**：
- [ ] 断网时所有图片显示深灰 fallback
- [ ] 上传损坏图片显示深灰 fallback
- [ ] 生成失败显示深灰 fallback

**优先级**：P0

---

### 3.4 选品灵感

**需求描述**：选品灵感加载有明确的进度和错误提示，用户能自助定位问题。

**状态展示**：

| 状态 | 用户看到 |
|------|---------|
| 加载中 | spinner |
| 加载成功（有空数据） | "暂无灵感"诚实空态 |
| 加载成功（有数据） | 商品列表 |
| 登录失效 | "登录已过期，请重新登录" |
| 服务暂不可用 | "服务暂不可用，请稍后重试" |
| 请求过于频繁 | "请求过于频繁，请稍后重试" |

**验收标准**：
- [ ] 错误文案明确说明问题类型
- [ ] Retry 按钮有效
- [ ] Retry 不创建草稿或消耗额度

**优先级**：P1

---

### 3.5 AI 方向推荐

**需求描述**：AI 推荐的创意方向有图片和来源依据，用户能理解为什么推荐这个方向。

**Direction 卡片内容**：
- 代表缩略图
- 来源标签
- `Why it fits` 说明
- 选中态

**验收标准**：
- [ ] 每个 Direction 有代表图
- [ ] 缺图时使用深灰 fallback
- [ ] 选中态明显

**优先级**：P1

---

### 3.6 Creative Direction 输入

**需求描述**：用户可以输入自己的创意方向，系统使用用户输入的内容生成。

**交互要求**：
- 输入框有明显边框和 label
- 键盘可进入和编辑
- Cancel 恢复原值
- Generate 只使用提交后的值

**验收标准**：
- [ ] Tab 可聚焦输入框
- [ ] Cancel 恢复编辑前的内容
- [ ] Generate 的内容等于输入框可见内容

**优先级**：P1

---

### 3.7 风格参考持久化

**需求描述**：用户选择的风格参考在关闭/重开后仍然保留，不需要重新选择。

**用户场景**：
1. 用户选择 2 张参考图
2. 关闭 AI Drawer
3. 再次打开 AI Drawer
4. 参考图仍然选中

**验收标准**：
- [ ] 关闭后重新打开，参考图保留
- [ ] 生成失败后重开，参考图保留
- [ ] 刷新页面后，参考图保留

**优先级**：P0

---

### 3.8 单一生成反馈

**需求描述**：AI 生成只有一个 toast，显示实时进度和最终结果。

**Toast 状态**：

| 生成状态 | Toast 显示 |
|---------|-----------|
| 提交中 | "正在生成..." |
| 生成成功 | "生成完成，已创建 N 张图片" |
| 部分成功 | "生成完成：N 张成功，M 张失败" |
| 全部失败 | "生成失败，请重试" |
| 状态未知 | "正在确认结果..." |

**禁止**：
- 同时显示"正在生成"和"未生成任何 Pin"
- 两条互相矛盾的 toast

**验收标准**：
- [ ] 只有一个 toast
- [ ] 状态变化时 toast 更新，不是新增
- [ ] 双击 Generate 不会产生多个 toast

**优先级**：P0

---

### 3.9 生成数量

**需求描述**：用户选择 2 组参考，每组生成 4 张，系统明确显示并生成 8 张。

**用户界面**：
```
参考图 A ─── 4 张
参考图 B ─── 4 张
─────────────────
总计：8 张
```

**验收标准**：
- [ ] UI 明确显示总数 8
- [ ] 生成 8 个 placeholder
- [ ] 计量算作 8

**优先级**：P0

---

### 3.10 Batch Edit 稳定性

**需求描述**：批量编辑在各种操作下不崩溃、不闪烁、不产生错误。

**操作场景**：
- 快速打开/关闭 Batch
- 快速选择/取消选择
- 刷新页面

**验收标准**：
- [ ] 无白屏
- [ ] 无 Error 弹窗
- [ ] 无控制台红色错误
- [ ] 双选才出现 Batch 按钮

**优先级**：P0

---

### 3.11 发布目标一致性

**需求描述**：卡片、设置页、批量编辑显示的发布目标完全一致。

**一致性问题场景**：

| 场景 | 卡片显示 | 实际情况 |
|------|---------|---------|
| 仅有 legacy Board | "Home Decor" | 未保存发布目标 |
| 无任何目标 | 空白 | 未保存发布目标 |
| 有明确目标 | "Pinterest / @user / Board A" | 已保存发布目标 |

**解决方案**：
- 无明确目标时显示"尚未选择发布目标"
- 引导用户打开目标选择器

**验收标准**：
- [ ] 无目标时显示"尚未选择发布目标"
- [ ] 有目标时显示真实账号和 Board
- [ ] Settings/单卡/Batch 三处一致

**优先级**：P0

---

### 3.12 可选排期

**需求描述**：发布时间默认折叠，用户明确选择后才出现时间选择器。

**交互流程**：
1. 默认：只显示"发布"按钮
2. 用户点击"设置发布时间"
3. 展开时间选择器
4. 用户可选择时间或取消
5. 取消后回到折叠状态

**验收标准**：
- [ ] 默认无时间字段
- [ ] 点击"设置发布时间"展开
- [ ] 点击"取消"或"不排期"折叠

**优先级**：P1

---

### 3.13 草稿同步

**需求描述**：批量编辑时，一个草稿的问题不影响其他草稿，用户能清楚知道每个草稿的状态。

**问题场景**：
- 5 个草稿同时提交
- 草稿 2 的 Board 不可用
- 结果：草稿 1,3,4,5 保存成功，草稿 2 需要修正

**用户可见状态**：
| 状态 | 含义 |
|------|------|
| 已保存 | 草稿已同步到服务器 |
| 仅本地 | 草稿在本地，等待同步 |
| 需要处理 | 草稿有问题，需要用户修正 |
| 正在同步 | 草稿正在上传 |

**验收标准**：
- [ ] 1 个失败 + 4 个成功 = 4 个 saved + 1 个 needs attention
- [ ] 点击 needs attention 显示具体原因
- [ ] 修正后只有修正项重试

**优先级**：P0

---

### 3.14 账户隔离

**需求描述**：用户 A 的数据和草稿不能出现在用户 B 的界面。

**场景测试**：
1. 用户 A 正在生成
2. 用户 A 登出
3. 用户 B 登录
4. 用户 B 看到空白界面，无用户 A 的数据
5. 用户 A 重新登录，恢复原状态

**验收标准**：
- [ ] 用户 B 看不到用户 A 的草稿
- [ ] 用户 B 看不到用户 A 的生成中状态
- [ ] 用户 A 重登后恢复原状态

**优先级**：P0

---

### 3.15 Studio 视觉规范

**桌面 (1440×900)**：
- 两列卡片布局
- Failed 使用低噪声 badge，不使用全宽 banner
- Publish 是唯一主 CTA
- Plan 只有一个控制

**移动 (390×844)**：
- 单列布局，无横向溢出
- Plan 全屏显示
- 按钮触控区域 ≥44px
- Toast 不遮挡主 CTA

**验收标准**：
- [ ] 桌面两列无横溢
- [ ] 移动单列无横溢
- [ ] 失败入口低噪声

**优先级**：P1

## 4. 非功能需求

### 4.1 性能

| 指标 | 目标 |
|------|------|
| 页面首次加载 | < 2s |
| Batch Edit 打开 | < 300ms |
| Draft 同步 | < 2s |
| Toast 响应 | < 100ms |

### 4.2 可靠性

| 场景 | 预期行为 |
|------|---------|
| 网络断开 | 本地草稿保留，恢复后自动同步 |
| 生成超时 | 30s 后显示失败，可重试 |
| 服务器错误 | 显示友好错误，不崩溃 |

### 4.3 安全

- 不在 console 输出 token、secret、password
- 不在截图/日志中包含敏感信息
- OAuth callback 错误不泄露原始信息
