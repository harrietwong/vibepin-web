### 4.1 本轮五处最小诚实修复(post-merge,均在隔离 worktree)

**fix-1 — backend 唯一 red 的真根因不是"契约漂移",是 Windows CRLF checkout 敏感。**
逐层证据:`STAGE0_CATALOG` 硬编码指向 `..._catalog_audit_20260828T050505Z.json`(非
latest-selector);该 json、被哈希的 `.sql`、测试文件三者 vs cd21adfe **逐字节相同**。
实测哈希:receipt 存 `1d0ff236…`(= git blob 的 **LF** 规范哈希 = `_canonical_lf_sha256`),
而 `core.autocrlf=true` 把 `.sql` 检出成 **CRLF**,`read_bytes()` 得 `8de0318c…` → 仅在
Windows 失败,Linux/生产(LF)恒通过。这是 v3.7 一处疏漏:该断言用了裸 `read_bytes()`,
而**紧邻下一行**的迁移哈希断言已用 `_canonical_lf_sha256`(同一 CRLF-robust helper)。
修复 = 让该断言改用 `_canonical_lf_sha256(STAGE0_CATALOG_QUERY_PATH)`,与邻行一致、与
receipt 的规范哈希一致;LF 下取值不变,CRLF 下同样通过。**未改任何 query 语义 / receipt /
生产**。单测复跑:该用例 1 passed;全量 1117 passed。

**fix-2 — `web/src/lib/social/publishFanout.ts` EOF 多余空行。**
文件以 `}\r\n\r\n` 结尾(committed blob 内的尾空行),`git diff --check` 报 "new blank
line at EOF"。删去多余尾行(1 deletion,保留 CRLF 约定不产生行尾 churn),`diff --check`
现 0 告警。

**fix-3 — Shopify connect route 重复 import 导致生产 build 失败。**
四线合并后 `web/src/app/api/integrations/shopify/connect/route.ts` 同时保留了两条完全相同的
`prepareShopifyConnect` import。`tsc --noEmit` 未暴露该集成产物，Next/Turbopack 首次 build
以 “defined multiple times” fail。最小修复仅删除重复 import，不改 OAuth 行为。再次 build
已通过编译、TypeScript、页面数据收集与 **71/71** 静态页面生成。

**fix-4 — 限定 `/api/generate` 的 Turbopack function trace。**
修复前 `route.js.nft.json` 实测追踪 **1,299 files / 55,719,444 bytes**，其中包括
151 个 `artifacts` 文件和 281 个测试脚本，却包含 **0** 个 `backend/generator.py` 引用；
既把无关测试资产打进函数包，也不能让 Vercel inline Python 真正可用。生产架构明确使用
`GENERATION_MODE=worker`，inline spawn 仅供本地/自托管，所以在动态 `spawn` 参数上加入
Turbopack 官方 ignore marker，并新增 source-lock 回归断言。修复后 build 不再报告该 warning，
trace 缩为 **106 files / 2,065,849 bytes**，`artifacts/scripts/public/backend` 引用均为 0；
production build 仍 exit 0、71/71 页面生成。

**fix-5 — v66/v67 缺独立 rollback 文件。**
原候选只有 forward migration。v67 是无状态 RPC，可用精确签名 `drop function if exists`
完整回滚；v66 若直接 drop `units` 会丢失已写入的附加账号购买数量，因此新增 fail-closed
rollback：没有列时幂等返回，全部 `units=1` 时允许 drop，存在任一非默认值时抛 P0001、
列和数量原样保留。PGlite 真执行证明值 3 在被拦截后仍为 3，清除阻断条件后可完成回滚；
v67 同时证明有排期拒删、无排期成功删除、rollback 后函数为 0 且重复 rollback 无错。
